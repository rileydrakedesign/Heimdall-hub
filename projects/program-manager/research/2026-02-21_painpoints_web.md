## Iteration 1 — Trust copy + “free forever” anchors

### Agent for X
- Pain points / objections:
  - Fear that tools will read/retain drafts, DMs, or private content; buyers want explicit statements about what the vendor *won’t* access.
  - ToS/anxiety: creators worry automation tools can lead to throttling/bans; they look for clear “what we do / don’t do” policies.
- Workflow expectations:
  - OAuth-based access to X; scheduling/publishing; basic analytics; minimal friction to revoke access.
- Channel / marketing tactics:
  - Trust artifacts (privacy policy, retention promises) are conversion assets—not only legal docs.
- Trust / privacy concerns:
  - Typefully explicitly states it will only access accounts to help with problems/bugs and won’t open drafts/posts unless asked; also states deletion timelines.
  URL: https://support.typefully.com/en/articles/8718444-privacy-policy

### Class Chat AI
- Pain points / objections:
  - Students/instructors want one place that replaces a messy stack (LMS forum + Slack + Zoom + polling).
- Workflow expectations:
  - Course feed Q&A + chatrooms + live sessions + lightweight lecture tooling.
- Channel / marketing tactics:
  - “Free forever” becomes the default expectation baseline for classroom comms.
- Trust / privacy concerns:
  - “Product-based business model” / “better interface” testimonials are used to contrast with legacy tooling.
  URL: https://campuswire.com/

## Iteration 3 — Pricing expectations shift to “credits + add-ons” + campus AI procurement posture

### Agent for X
- Pain points / objections:
  - Confusion/friction when X is “sort of supported” but not fully; buyers accept X carve-outs if they’re explicit.
- Workflow expectations:
  - Separate X add-on pricing is increasingly normalized in social suites.
- Channel / marketing tactics:
  - Pricing UX that explains upstream platform costs (API) reduces backlash.
- Trust / privacy concerns:
  - Metricool shows Twitter/X as an explicit add-on (+$5 per connected account) and excludes X from free plan—this reinforces that we should be explicit about X limits/cost drivers.
  URL: https://metricool.com/pricing/
