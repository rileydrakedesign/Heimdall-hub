# Research Brief — 2026-02-23

Priority order:
1) **Agent for X**
2) **Class Chat AI**

## What changed / what we learned today (high signal)

### 1) “Is it safe?” has moved onto the pricing page (plain-English, no-hacks claims)
- Taplio’s pricing FAQ answers safety directly: “behaves exactly like a real user… doesn’t rely on hacks… respects normal usage patterns.”
- Implication for Agent for X: we need a **canonical Automation Safety Policy** page and we should write it in plain English (not just legalese), with explicit caps and “what we never do.”
- Source:
  - https://taplio.com/pricing

### 2) X creator tools are bundling the full growth loop (library + scheduling + automations + CRM)
- Tweet Hunter’s pricing positions: 2M+ viral library, scheduling, evergreen queues, and automation primitives like Auto-DM / Auto-retweet plus “X CRM.”
- Implication: Agent for X should be positioned as “full loop,” or at least have a crisp story for which parts of the loop it covers and which it won’t.
- Source:
  - https://tweethunter.io/pricing

### 3) Edu pricing templates: teacher-free + small consumer subscription + district request pricing
- Khanmigo pricing shows a clean buyer split: Teachers free; Learners/Families $4/mo; District tools request pricing (SSO/rostering, data, CS, pro learning).
- Implication: Class Chat AI can copy this shape: **free instructor wedge** (or free limited student chat) → paid family/individual → district/admin tier.
- Source:
  - https://www.khanmigo.ai/pricing

### 4) “We don’t sell student data” is still the simplest trust wedge (and it travels)
- Campuswire FAQ claims: FERPA-compliant, “we don’t sell student data… or advertise.” Regardless of whether buyers verify every detail, this is the language that gets repeated internally.
- Implication: Class Chat AI should have an equally legible trust statement, plus explicit retention/deletion controls.
- Source:
  - https://medium.com/campuswire/campuswire-faqs-c6993d93cb29

### 5) Enterprise AI trust checklists are leaking into edu procurement (no-training-by-default, encryption, retention controls)
- OpenAI’s business-data page is a good “benchmark doc” that procurement-minded buyers will reference.
- Implication: Class Chat AI should be able to say (truthfully) equivalents to: no training by default, encryption at rest/in transit, and configurable retention/deletion.
- Source:
  - https://openai.com/business-data/

## Implications

### Agent for X
- Product:
  - Ship a canonical **Automation Safety Policy** page (plain English) with: caps/budgets, what we automate vs never automate, and a “why these caps exist” narrative.
  - Add self-serve **pause/revoke** UX (risk-reversal + trust).
- GTM:
  - Make safety copy and caps linkable (affiliates, replies, docs).

### Class Chat AI
- Product:
  - Package by buyer: teacher/instructor wedge, learner/family subscription, district tier with SSO/rostering/analytics.
  - Trust surfaces: “we don’t sell student data,” explicit retention/deletion, citations/grounding.
- GTM:
  - Borrow the Khanmigo-style buyer split in the landing page IA (tabs/sections by buyer).
