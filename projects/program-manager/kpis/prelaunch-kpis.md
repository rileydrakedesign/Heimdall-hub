# Pre-Launch KPIs (Portfolio)

**Updated:** 2026-02-06

Pre-launch KPI goal is to avoid fake precision while still creating a tight feedback loop.

---

## KPI tiers

### Tier 1 — Must-track (weekly)
These are the only numbers we treat as “portfolio vital signs” pre-launch.

1) **Waitlist conversion rate**
- Definition: waitlist submits / unique visits
- Why: best proxy for clarity + desire.

2) **Qualified conversations**
- Definition: # of 1:1 threads/calls with ICP where pain + willingness confirmed.
- Why: fastest route to product/offer fit.

3) **Time-to-first-value (TTV) proxy**
- Definition: time from first touch → first moment user says “that’s useful.”
- Why: prevents building unusable products.

4) **Asset throughput**
- Definition: # usable demos / before-after packs / distribution-ready posts created.
- Why: GTM progress is constrained by assets early.

### Tier 2 — Helpful diagnostics (optional)
- Landing page CTRs (hero CTA click rate)
- Email signup confirmation rate (if double opt-in)
- Content performance: impressions, profile visits, link clicks

---

## Per-product KPI definitions

### AIStudyBuddy
- **Primary:** waitlist conversion rate (target: ≥8% from targeted traffic)
- **Secondary:** # of “trust pain” confirmations (quotes per week; target: 10)
- **TTV proxy:** user gets a cited answer they trust within 5 minutes (target: ≥50%)

### Agent for X
- **Primary:** qualified conversations/week (target: 10 DM threads)
- **Secondary:** waitlist conversion rate (target: ≥10% targeted)
- **TTV proxy:** creator receives 3 drafts they’d actually post within 24h (target: ≥60%)

## Logging plan (do this even when busy)

- Daily (5 min): append any events to `projects/program-manager/kpis/kpi-log.md`
- Weekly (15 min): summarize deltas and decisions in the PM weekly brief.

Logging rules:
- Log **what happened**, **what it means**, **what we’ll do next**.
- If tracking is broken, log that as the event.
