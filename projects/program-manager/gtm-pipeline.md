# GTM + Growth Pipeline (v1)

The canonical lifecycle for ideas → products → growth.

## Stages

### 0) Idea capture
**Output:** a one-page `idea.md` entry.
**Gate:** problem, user, and hypothesis stated in plain language.

### 1) Validation
**Goal:** prove demand signal before heavy build.
**Outputs:**
- target persona + job-to-be-done
- value prop (1 sentence)
- channel hypothesis
- success metric + measurement plan
- 1–2 low-effort tests (waitlist, outreach, pricing page, ads, content)

**Gate:** clear signal + next best test chosen.

### 2) Build (MVP)
**Goal:** smallest product that creates the promised outcome.
**Outputs:**
- scope (must-have only)
- analytics/events plan
- onboarding funnel map

**Gate:** MVP shipped + instrumented.

### 3) GTM execution
**Goal:** consistent acquisition loop.
**Outputs:**
- launch plan
- content + distribution calendar
- channel experiments backlog

**Gate:** repeatable weekly cadence.

### 4) Growth (0 → 1000)
**Goal:** iterate on funnel + retention.
**Outputs:**
- weekly experiments (A/B or quasi-tests)
- retention loops + activation improvements
- user feedback intake → decisions → shipped changes

**Gate:** sustainable acquisition + retention and cost control.

## Key principles
- Every idea has a measurable hypothesis.
- Every experiment has: metric, segment, duration, stop rule.
- Do not run “random improvements”; tie changes to funnel stage + KPI.
